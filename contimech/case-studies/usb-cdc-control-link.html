Driverless USB CDC control interface for a bench controller

Excerpt from a reference specification for controlling a bench I/O controller from a PC over USB: by an engineer at a terminal, by a Python script and by test automation. It is a synthetic public reference built on the same engineering approach we use in client work. It does not reproduce any client protocol: message set, framing and values are our own illustrative choices.

1Scope

This document specifies the control interface between a host PC and a bench controller with digital outputs, digital inputs and analog measurement channels. It covers the USB transport, framing, messages, session behaviour, timing and error handling. Controller hardware and I/O electrical characteristics are out of scope.

3Requirements

  1. USB-SYS-001

    The controller shall enumerate as a USB CDC-ACM device and operate on the supported host operating systems without installing a driver.

    T

    Lab PCs are locked down; no admin rights.

  2. USB-SYS-002

    The USB iSerialNumber shall be derived from the MCU unique ID and shall be stable across power cycles.

    IT

    Several units on one PC need stable names.

  3. USB-SYS-010

    In ACTIVE, if no valid frame is received for T_HB = 1000 ms, the controller shall set all outputs to their safe state, enter SAFE and latch the reason.

    T

    A crashed script or pulled cable must leave the bench safe.

  4. USB-PRO-001

    Each frame shall be COBS-encoded and terminated by a single 0x00 byte.

    I

    Unambiguous boundary in a byte stream; bounded overhead.

  5. USB-PRO-002

    Each frame shall carry a CRC-16/CCITT-FALSE over header and payload, computed before encoding.

    IT

    Detects corruption the transport does not report.

  6. USB-PRO-003

    The controller shall answer every valid request with exactly one response carrying the same SEQ.

    T

    Silence then means only “not received”.

  7. USB-PRO-004

    A request repeating the SEQ of the last executed request shall be answered from the stored response without re-execution.

    T

    Retries must be idempotent.

  8. USB-PRO-005

    Frames failing decoding, length or CRC checks shall be discarded without response and counted.

    T

    A response to garbage could be mistaken for a reply.

  9. USB-TIM-001

    Responses to non-measurement commands shall be sent within 20 ms of request reception.

    T

    Bounds host timeout and retry budget.

  10. USB-SW-001

    The host library shall reopen a controller by serial number within 2 s of its re-enumeration.

    T

    Recovery without operator action.

  11. USB-SW-002

    After (re)connection the host shall send HELLO before any other command; the response shall report state and the last safe-state reason.

    T

    The host never assumes the old state.

Verification: T test · A analysis · I inspection · D demonstration

4Transport

ParameterValue
USB2.0 full speed, 12 Mbit/s
ClassCDC-ACM: one bulk IN, one bulk OUT (64-byte max packet), one interrupt notification endpoint
Line codingAccepted and ignored; no baud-rate dependency
DTR / RTSIgnored. Session state is carried by the protocol, because not every host asserts DTR
IdentificationVendor-assigned VID/PID; iSerialNumber from MCU unique ID

5Frame format

OffsetSizeFieldDescription
01VERProtocol version, 0x01
11SEQSequence number 0..255, wraps; set by host, echoed in response
21MSGMessage identifier, see §6
31FLAGSbit 0 response · bit 1 error · bits 7..2 reserved, 0
42LENPayload length, 0..256
6LENPAYLOADMessage-specific
6+LEN2CRCCRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) over bytes 0..5+LEN

The frame is then COBS-encoded and followed by 0x00. COBS was chosen over SLIP-style escaping because its overhead is bounded:

encoded size ≤ n + ⌈n / 254⌉ + 1 (n = unencoded frame size) largest frame: n = 6 + 256 + 2 = 264 → ≤ 267 bytes → 5 bulk packets of 64 bytes SLIP worst case: every byte escaped → 2n + 1 = 529 bytes

Example: GET_STATUS, SEQ 0x2A, no payload.

unencoded   01 2A 10 00 00 00 0D 1E        CRC-16 = 0x1E0D
on the wire 04 01 2A 10 01 01 03 0D 1E 00

Example: SET_OUTPUT channel 3 on, SEQ 0x2B.

unencoded   01 2B 20 00 02 00 03 01 26 CE  CRC-16 = 0xCE26
on the wire 04 01 2B 20 02 02 05 03 01 26 CE 00
