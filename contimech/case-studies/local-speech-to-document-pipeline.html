Local speech-to-document pipeline with human approval

A pipeline that takes a finished lecture recording, transcribes it, turns the transcript into structured notes, removes personal details, and publishes the result only after the teacher approves it. Processing runs on the owner's own server.

Domain
Education, document automation
Stack
Linux server, ffmpeg, faster-whisper, small language model
Runs on
Own server, GPU with CPU fallback
Services
1.1 Prototyping · 2.3 Software

Task

Transcription is the easy part. After a lecture someone still has to move the file, extract the audio, transcribe it, turn spoken language into a readable structure, remove names and other personal details, prepare teaching material, get approval and publish. The pipeline was built around that whole chain, with the teacher keeping the final say.

How it works

  1. Capture. A finished recording is picked up and moved to the processing server.
  2. Transcribe. Audio is extracted (16 kHz mono), the language is detected and faster-whisper produces a timestamped transcript.
  3. Structure. A small language model and course templates turn the transcript into lecture notes and a methodological guide.
  4. Sanitise. A language-model pass removes personal and sensitive details.
  5. Approve and publish. The teacher reviews the result. Nothing is published before approval; approved material goes straight to the course website.

Runtime behaviour

The converter prefers GPU acceleration and falls back to CPU if CUDA or a library fails. Slower, but the result is preserved. Each stage can be resumed, so a failure late in the chain does not repeat the transcription.
